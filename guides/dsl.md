# Writing specs without learning TLA+: the DSL

Notary's specs are TLA+ files checked by TLC. If you don't want to read or
write TLA+, the DSL (`Notary.DSL`) lets you write the same spec *in Elixir*,
and Notary generates the `.tla` and `.cfg` from it. Everything downstream
works unchanged: the model check, the state graph, the lock file, the
compiler-style diagnostics, conformance.

This guide ports the two specs from the other guides — the Greeter from
[Getting Started](getting-started.md) and the [rate limiter](rate-limiter.md)
— to the DSL. For a one-page lookup of every DSL form and the TLA+ it
generates, see the [DSL ↔ TLA+ cheatsheet](dsl-cheatsheet.cheatmd).

## The same Greeter spec, in Elixir

The [Getting Started guide](getting-started.md) writes `specs/Greeter.tla`
by hand:

```tla
VARIABLE greeted

TypeOK == greeted \in BOOLEAN

Init == greeted = FALSE

Greet == /\ greeted = FALSE
         /\ greeted' = TRUE

Next == Greet

Spec == Init /\ [][Next]_greeted
```

The equivalent DSL module (put it in `test/support/specs/greeter.ex`, so it
compiles in the test env):

```elixir
defmodule HelloNotary.Specs.Greeter do
  use Notary.DSL, name: "Greeter"

  description "Greeter: says 'Hello, world!' exactly once."

  variable greeted: boolean()

  initial greeted: false

  action Greet do
    guard greeted == false
    assign greeted: true
  end
end
```

Run `mix notary.compile` (or any `mix notary.*` task — they sync first) and
Notary writes `specs/Greeter.tla` and `specs/Greeter.cfg`, marked with a
`\* GENERATED by Notary.DSL` header. The generated file checked in and
human-reviewed is the *real* spec: it is what TLC checks, what the lock
covers, and what an LLM reads.

What maps to what:

| DSL | TLA+ |
|---|---|
| `variable greeted: boolean()` | `greeted \in BOOLEAN` (a `TypeOK` invariant) |
| `initial greeted: false` | `Init == greeted = FALSE` |
| `action Greet do ... end` | a disjunct of `Next` |
| `guard greeted == false` | `greeted = FALSE` |
| `assign greeted: true` | `greeted' = TRUE` |

`assign/1` sets what changes. Anything an action doesn't mention is
automatically `UNCHANGED` — the mechanical bookkeeping raw TLA+ makes you
write yourself. (Pass `explicit_unchanged: true` to an action to write it
yourself and have missing variables fail compilation instead.)

## The rate limiter

From the [rate-limiter guide](rate-limiter.md): at most `Limit` requests per
window. The DSL version:

```elixir
defmodule RateLimiter.Specs.Limiter do
  use Notary.DSL, name: "Limiter"

  description "Allow at most Limit requests per time window."

  constant limit: 3                    # CONSTANT + the .cfg model value in one line
  variable count: 0..limit             # a TLA+ range

  initial count: 0

  # A request is accepted only while the window has room left.
  action Request do
    guard count < limit
    assign count: count + 1
  end

  # The window passes; time is outside our code's control, so this is an
  # external action with no guard.
  action Tick do
    assign count: 0
  end
end
```

Same model as the guide's hand-written spec: 4 states, `Request` climbs to
the limit, `Tick` resets. `mix notary.graph Limiter --format mermaid` shows
exactly the diagram in that guide.

## Parameterized actions: the bank

Guards with parameters (the README's `Bank` spec) translate too:

```elixir
defmodule MyApp.Specs.Bank do
  use Notary.DSL, name: "Bank"

  constant max_bal: 4
  variable balance: 0..max_bal
  variable last_op: ["none", "deposit", "withdraw"]

  initial balance: 0, last_op: "none"

  action Deposit, param: 1..2 do
    guard balance + param <= max_bal
    assign balance: balance + param, last_op: "deposit"
  end

  action Withdraw, param: 1..2 do
    guard param <= balance
    assign balance: balance - param, last_op: "withdraw"
  end
end
```

`param: 1..2` declares the parameter *and* its domain: the generated `Next`
becomes `\E param \in 1..2 : Deposit(param) \/ ...`, and the same domain
provides the generator for your mapping module (below). TLC's state-graph
labels strip the arguments, so `mix notary.graph` and conformance see
`Deposit`, exactly as in the hand-written spec.

## Properties and fairness

The Liveness story from [the README](../README.md#limits-v1) carries over:
fairness and temporal properties are first-class (`always/1`,
`eventually/1`, `leads_to/2`):

```elixir
defmodule MyApp.Specs.Watchdog do
  use Notary.DSL, name: "Watchdog"

  variable caller: ["alive", "dead"]
  variable os: ["none", "alive", "exited", "killed"]

  initial caller: "alive", os: "none"

  action Start do
    guard caller == "alive" and os == "none"
    assign os: "alive"
  end

  action Reap, doc: "The watchdog notices the dead caller and kills TLC." do
    guard caller == "dead" and os == "alive"
    assign os: "killed"
  end

  fair Reap

  property NoOrphans,
    doc: "A dead caller never leaves TLC running forever.",
    do: leads_to(caller == "dead", os != "alive")
end
```

`fair Reap` generates `WF_vars(Reap)` — Notary's internal-action settle
check reads it from the generated file exactly as from a hand-written spec.

## The mapping module, with derived generators

`use Notary.Conformance.DSL` derives `actions/0` from the DSL spec's
parameter domains — one source of truth for what the spec says and what the
runner drives:

```elixir
defmodule MyApp.Specs.BankMapping do
  use Notary.Conformance.DSL, from: MyApp.Specs.Bank

  def init, do: start_app()
  # param: 1..2 became StreamData.fixed_map(%{param: StreamData.integer(1..2)})
  def action("Deposit", %{param: p}, ctx), do: ...
  def project(pid), do: %{"balance" => ..., "last_op" => ...}
end
```

Override any action's generator: `def __gen__("Deposit"), do:
StreamData.integer(1..100)`.

## The expression subset

The [cheatsheet](dsl-cheatsheet.cheatmd) has the full table (arithmetic, `<`,
`and`/`or`/`not`, sets, `if/else`, records `%{a: 1}` → `[a |-> 1]`,
sequences `[a, b]` → `<<a, b>>`, `head/tail/length/...`). Anything outside
it fails *compilation* with the offending code quoted — no silent
mistranslations. For what the surface doesn't cover (quantifiers over
several variables, set comprehensions), the escape hatch is raw TLA+:

```elixir
raw ~S"""
TwoBills(amount) == amount' = amount + 1 \/ amount' = amount + 2
"""
```

`raw` definitions are spliced into the generated module before `Next`.
Graduate out of the DSL gradually: the generated `.tla` is right there, and
a spec can start raw and stay raw — both are first-class.

## The workflow, with the DSL

Everything else is unchanged:

```bash
mix notary.compile            # DSL modules -> specs/*.tla + *.cfg
mix notary.check Greeter      # TLC on the generated spec
mix notary.lock               # review + lock the GENERATED files
mix notary.verify             # lock check, model check, conformance
```

LLM agents follow `specs/AGENTS.md` as before: the generated files are the
specs they must implement and never edit — to change what the spec says,
change the DSL module and recompile.
